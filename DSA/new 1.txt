   instance instead of replicating it.

Nested class
// Save this file as Main.java

/*
================================================================================
                         NESTED CLASSES IN JAVA
================================================================================
A nested class is a class declared inside another class. They are split into:

1. Static Nested Class
   - Declared with the 'static' keyword.
   - Does NOT have access to non-static variables/methods of the outer class.
   - Can be instantiated without creating an outer class object.

2. Inner Class (Non-Static Nested Class)
   - Declared without the 'static' keyword.
   - Has direct access to all variables/methods of the outer class (even private ones).
   - Requires an outer class object to be instantiated.
================================================================================
*/

class Outer {
    String outerField = "Outer Class Instance Field";
    static String staticOuterField = "Outer Class Static Field";

    // 1. STATIC NESTED CLASS
    static class StaticNestedClass {
        void display() {
            // System.out.println(outerField); // ERROR: Cannot access non-static field
            System.out.println("Inside Static Nested Class: " + staticOuterField);
        }
    }

    // 2. INNER CLASS (NON-STATIC)
    class InnerClass {
        void display() {
            // Can access both static and instance fields freely
            System.out.println("Inside Inner Class: " + outerField + " | " + staticOuterField);
        }
    }
}

public class Main {
    public static void main(String[] args) {
        // Instantiating the Static Nested Class (No Outer object needed)
        Outer.StaticNestedClass staticNested = new Outer.StaticNestedClass();
        staticNested.display();

        // Instantiating the Inner Class (Requires an Outer object first)
        Outer outerObj = new Outer();
        Outer.InnerClass inner = outerObj.new InnerClass();
        inner.display();
    }
}

    Parent() {
        System.out.println("Parent Constructor called");
    }

    void show() {
        System.out.println("Method inside Parent Class");
    }
}

class Child extends Parent {
    String name = "Child Variable";

    Child() {
        // 1. Invoking parent constructor using super()
        // Must be the first statement in the constructor
        super(); 
        System.out.println("Child Constructor called");
    }

    void display() {
        // 2. Accessing variables
        System.out.println(this.name);  // Output: Child Variable
        System.out.println(super.name); // Output: Parent Variable

        // 3. Invoking methods
        this.show();  // Calls inherited show() method (or overridden one)
        super.show(); // Explicitly calls parent show() method
    }
}

public class Main {
    public static void main(String[] args) {
        Child obj = new Child();
        obj.display();
    }
}

// Save this file as Main.java

class Account {
    // 1. Private variables hide data
    private double balance = 1000.0;

    // 2. Getter (Read access)
    public double getBalance() {
        return balance;
    }

    // 3. Setter (Write access with validation)
    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }
}

public class Main {
    public static void main(String[] args) {
        Account acc = new Account();
        
        acc.deposit(500); // Controlled update
        System.out.println("Balance: " + acc.getBalance()); // Controlled read
    }
}

================================================================================
                       TYPES OF INHERITANCE IN JAVA
================================================================================

Java supports three primary types of class inheritance:

1. Single Inheritance
   - Description:   A subclass inherits from a single superclass.
   - Visual Layout: A -> B

2. Multilevel Inheritance
   - Description:   A subclass inherits from a child class, creating a chain.
   - Visual Layout: A -> B -> C

3. Hierarchical Inheritance
   - Description:   Multiple subclasses inherit from a single superclass.
   - Visual Layout: A -> B and A -> C

--------------------------------------------------------------------------------
NOTE ON MULTIPLE INHERITANCE:
Java DOES NOT support Multiple Inheritance with classes (e.g., Class C extending
both Class A and Class B). This avoids the Diamond Problem, which causes 
ambiguity when two parents have a method with the same signature. 

However, multiple inheritance can be achieved in Java using Interfaces.

================================================================================
         HOW INTERFACES SOLVE MULTIPLE INHERITANCE IN JAVA
================================================================================

Java bans multiple inheritance with CLASSES to avoid the "Diamond Problem." 
If Class C extended both Class A and Class B, and both parents had a method 
named "run()", Class C wouldn't know which parent's "run()" method to execute. 

Interfaces completely solve this problem using the following rules:

1. NO IMPLEMENTATION DETAILS (NO METHOD BODIES)
   An interface only declares *what* a class should do, not *how* to do it. 
   It has no code blocks inside its methods. Because there is no actual code 
   to inherit, there is no conflict between parent behaviors.

2. THE CHILD CLASS MAKES THE RULES
   If Class C implements both Interface A and Interface B, Class C is forced 
   to write the actual method body itself. The child class provides the one 
   and only implementation.

3. DUPLICATE METHODS COLLAPSE INTO ONE
   If Interface A and Interface B both demand a method named "run()", the 
   compiler doesn't get confused. From the child class's perspective, both 
   interfaces are just asking for the same requirement. The child class 
   implements "run()" exactly ONCE, fulfilling the contract for both parents 
   at the same time.

Summary: 
Classes inherit implementation (which causes conflicts). Interfaces inherit 
only specifications (which eliminates conflicts).

================================================================================
                         POLYMORPHISM IN JAVA
================================================================================
Polymorphism means "many forms". It allows an action to be performed in 
different ways. There are two main types:

1. Compile-Time Polymorphism (Method Overloading)
   - Same method name, but different parameters within the same class.
   - Handled by the compiler based on the arguments passed.

2. Runtime Polymorphism (Method Overriding)
   - Same method name and parameters, but redefined in a subclass.
   - Handled at runtime based on the actual object type created.
================================================================================


class Calculator {
    // 1. COMPILE-TIME POLYMORPHISM (Overloading)
    // Add two integers
    int add(int a, int b) {
        return a + b;
    }
    
    // Add three integers (same name, different parameters)
    int add(int a, int b, int c) {
        return a + b + c;
    }
}

class Animal {
    // 2. RUNTIME POLYMORPHISM (Overriding)
    void sound() {
        System.out.println("Animal makes a sound");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}

public class Main {
    public static void main(String[] args) {
        // Testing Compile-Time Polymorphism
        Calculator calc = new Calculator();
        System.out.println(calc.add(5, 10));     // Calls 2-parameter method
        System.out.println(calc.add(5, 10, 15)); // Calls 3-parameter method

        // Testing Runtime Polymorphism (Upcasting)
        Animal myAnimal = new Dog(); 
        myAnimal.sound(); // Output: "Dog barks" (Decided at runtime)
    }
}
